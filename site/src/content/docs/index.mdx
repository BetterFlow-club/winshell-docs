## Why winshell

<CardGrid>
  <Card title="Native engine, no Electron" icon="seti:html">
    Surfaces are drawn by **WebView2**, the Chromium engine of Microsoft Edge that ships with Windows 10 and 11. Nothing to bundle, and Windows keeps it up to date. All surfaces share one browser and one GPU process.
  </Card>
  <Card title="Light by design" icon="rocket">
    The daemon is native Zig. Audio, Wi-Fi, media, stats and the rest **start only when a page subscribes** and stop when it leaves, so nothing polls in the background. Window tracking is event driven.
  </Card>
  <Card title="You decide the cost" icon="setting">
    Each surface is one page, roughly **50–70 MB**. A single bar is cheap; a full desktop with launcher, control center and widgets costs more. Aurora, the default shell, idles **well under 1% CPU**, even with its live audio visualizer.
  </Card>
  <Card title="Out of the way in games" icon="star">
    On a fullscreen app, surfaces drop behind it so Windows keeps its fast fullscreen path. They're back the moment you leave (about 4 ms).
  </Card>
  <Card title="The whole system, typed" icon="seti:typescript">
    Windows, monitors, audio, media with cover art, Wi-Fi, Bluetooth, battery, brightness, notifications, tray icons, apps, wallpaper colors. One typed SDK, over 20 live topics.
  </Card>
  <Card title="Safe to try" icon="approve-check">
    The Windows taskbar is only hidden while winshell runs, and it always comes back: on quit, on a crash (a watchdog restores it), or with `winshellctl restore-taskbar`.
  </Card>
</CardGrid>

## A bar in a few lines

```ts
import { shell } from "@winshell/sdk";

// The focused window, live.
shell.subscribe("windows", ({ windows, focused }) => {
  title.textContent = windows.find((w) => w.hwnd === focused)?.title ?? "";
});

// Volume: shows the level, click to mute.
shell.subscribe("audio", ({ output }) => {
  volume.textContent = output ? `${Math.round(output.volume * 100)}%` : "–";
});
volume.onclick = () => shell.invoke("audio.toggleMute");

// The clock opens a calendar popup underneath it.
clock.onclick = () => shell.surface.toggle("calendar", { anchor: clock });
```

```bash
npm create winshell-shell my-shell   # this, ready to run
```

## How it fits together

```
winshelld          native daemon: windows, hotkeys,
  │                 config, services (audio, wifi, …)
  ├─ winshell-host  a WebView2 window per surface
  │    └─ pages     your HTML, with @winshell/sdk
  └─ winshellctl    command line: start, inspect, script
```

<p class="ws-note">Memory and CPU depend on the shell you run: how many surfaces it has, and how much each page does. The numbers above are Aurora's on a 16-thread desktop.</p>
